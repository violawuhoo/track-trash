## 2. 世界结构

```
世界矩形：1440 × 1440（世界单位，1 单位 ≈ 1px @ zoom 1）
星球本体：圆心 (720,720)，半径 640，占满世界
星球外：留 80 单位环带作为「探索边界」，走到即停
```

**边界方式**（以 `docs/CONTRACT-v2.md` §9 为准，本节原「水平回绕」已否决）

- **不做水平回绕**：圆形星球 + 方形世界 + 取模回绕三者几何上自相矛盾——在 `y=200` 处越界，回绕点已经落在星球外。
- 角色与物品点统一夹在圆形范围内（`walkableRadius` / `itemRadius`），走到星球边缘即停。
- 球感由圆形描边 + 相机夹紧提供；若日后要真周游，改渲染为横向平铺，规则层不受影响。


**区域映射**（沿用 v1.0 的四个 AreaId，改为星球上的扇区地标）

| AreaId | 地标 | 极坐标位置 | 解锁 |
|---|---|---|---|
| `crash` | 坠毁点（出生点） | 圆心偏南，r=0 | 初始 |
| `junkyard` | 垃圾山 | 东，θ=0°，r=420 | 阶段 1 完成 |
| `market` | 外星集市废墟 | 北，θ=-90°，r=420 | 阶段 2 完成 |
| `cave` | 怪石洞窟 | 西，θ=180°，r=420 | 阶段 2 完成 |

未解锁区域：地面覆盖一层浅墨色「雾障」贴图，走进去被弹回并触发一句台词。

## 3. 视觉系统

### 3.1 色盘：不新增色相，只加明度阶

现有 5 个荧光色（橙 / 薄荷 / 紫 / 粉 / 黄）够用。**必须新增的只有 3 个中性阶**：

| 变量 | 值 | 用途 |
|---|---|---|
| `--space` | `#ECE1C9` | 星球外的「太空」。浅色，不压暗屏幕。星球像浮在一张旧纸上 |
| `--planet` | `#FFFDF7` | 星球表面 |
| `--planet-shade` | `#F1E6D0` | 地面斑块、投影、山体 |

**关键决策：太空用浅色，不用深色。**
理由：深色太空会毁掉贴纸拼贴的整套语言（墨黑描边在深底上消失），且手机大面积深色 + 小字可读性差。浅色太空 + 白色星球 + 墨黑 3px 描边 = 「一张纸上画了个圆」，这才是这个项目该有的样子。

### 3.2 形状语言

| 元素 | 规范 |
|---|---|
| 星球边界 | 3px `--ink` 实线圆 + 外侧 1px 虚线圆（offset 12，`--ink` 30%），表示大气层 |
| 地面斑块 | 6–9 边不规则多边形，`--planet-shade` 实心，无描边，随机旋转 |
| 山 / 石 | 三角或多边形，`--paper` 填充 + 2px `--ink` 描边 |
| 物品贴纸 | 现有 `ItemIcon` SVG，缩放到 28–36 单位，底部加 2px 偏移的 `--planet-shade` 椭圆投影 |
| 小人 | 24×36 单位。墨黑剪影 + 橙色头巾，2px `--ink` 描边。四向朝向用 4 张 sprite 水平翻转 |
| 可交互高亮 | 橙色虚线圆环 r=28，`stroke-dasharray: 4 4`，整体上下浮动 ±2（正弦，1.2s） |

**禁止**：渐变、模糊、发光、外发光。所有阴影都是实心偏移色块。

### 3.3 动效

| 场景 | 规范 |
|---|---|
| 小人移动 | 线性位移 + 6 帧走路循环，速度 140 单位/秒，到点前 40 单位 ease-out |
| 拾取 | 物品缩放 1 → 1.3 → 0，向背包按钮方向飞入，240ms |
| 首次拾取 | 额外弹 toast + 停顿 0.4s |
| 相机跟随 | 死区跟随，小人在屏幕中心 40% 区域内不动相机，超出才平移 |
| 区域切换 | 不做转场。走到云雾边界时雾层渐显（opacity 0 → 0.35，300ms） |

## 4. 界面层级

### 4.1 手机（< 768px）

```
┌──────────────────────────────┐
│ HUD：第 n 天 · 阶段 n   背包 4 │  ← 浮动，不透明纸卡片，高 36px
│                              │
│      [ 全屏 PixiJS 画布 ]      │
│      星球铺满，相机跟随         │
│                              │
│  缺：能粘的东西                 │  ← 左下角，一句话，可点开展开
│                              │
│                       ○ 拾取  │  ← 右下角，仅对焦时出现，直径 56px
│ ┌──────────────────────────┐ │
│ │ 这地方连风都懒得吹。       │ │  ← 对话条，高 44px，可上滑收起
│ └──────────────────────────┘ │
└──────────────────────────────┘
```

- 画布 `100dvh`，不用 `100vh`（iOS 地址栏）。
- HUD 与对话条 `position: absolute`，`pointer-events: none`，子元素单独开启。
- 合成台**不常驻**：点 HUD 右侧背包 → 全屏抽屉 → 底部双槽 + 合成按钮。
- **HUD 不做半透明底**（2026-10-19 修订）：世界底色随相机移动而变化，12px 字压在动态半透明底上对比度无法验证。改为不透明纸卡片 + `--shadow-sm`，见 `docs/design/DESIGN-SYSTEM.md`。


### 4.2 网页（≥ 1024px）

- 画布铺满，星球显示半径控制在视口高度 1.2 倍。
- 合成台作为右侧 320px 常驻侧栏（有空间，不必藏）。
- 背包侧栏可折叠。
- 支持 WASD / 方向键，与点击移动并行。

### 4.3 平板（768–1023px）

手机布局 + 合成台从底部抽屉出，宽度锁 420px 居中。

## 5. 交互规范

| 项 | 规范 |
|---|---|
| 移动 | 点击/轻触地面 → 小人直线走过去。不做寻路，不做碰撞绕行（星球上无密障碍物） |
| 拾取 | 进入物品 40 单位半径**自动拾取**，不设按钮。右下角按钮只是「批量拾取附近」的备用 |
| 对焦提示 | 距离 < 80 单位时，目标描边变橙 + 名称浮出 |
| 触控目标 | 所有可点元素 ≥ 44×44 CSS px |
| 拖拽 | **禁用**。移动端不可靠，且与点击移动冲突 |
| 长按 | 保留，仅用于查看物品详情 |
| 双指缩放 | 允许 0.8×–1.6×，不影响世界逻辑 |
| 相机 | 不做自由拖拽。相机只跟随小人，避免玩家把小人和视口走散 |

**为什么不用虚拟摇杆**：无战斗、无精确操作需求。摇杆会遮挡左下角 1/6 屏幕，且多点触控要额外处理。点击移动单手可玩，也延续了现有「点击」的操作基因。

## 6. 玩法规则改造

### 6.1 时间（**待你确认**）

推荐方案：**拾取不推进时间，合成 +1 天**。
- 天数从「限制资源的倒计时」变成「你在这颗星球待了多久」的叙事计数器。
- 保留第 7 天访客事件，触发条件改为「第 7 天当天首次合成时」。
- 好处：开放世界不该用时间压迫探索；合成是核心动作，天然成为节拍器。

备选：
- A. 每拾取 3 件 +1 天（节奏快，但会让玩家不敢捡东西）
- B. 跨区域 +1 天（可被绕开，节拍不稳）

### 6.2 物品刷新

- 星球上常驻 **12–18 个物品点**，按区域池分布。
- 每次合成（即 +1 天）后，**全星球重新分布**。已拾取的格子空出来，新的填进去。
- 未拾取的物品在刷新时保留位置，只补空缺。
- 刷新时物品尺寸做 0 → 1 的缩放动画，让玩家看见「东西又长出来了」。

### 6.3 硬保底的空间化（**不可回退**）

原逻辑：`pickSearch` 保证缺标签的物品必定被搜出来。
新逻辑：**保证缺标签的物品在星球上必定有一个可见的地面点。**

```
distribute(progress, bag, day):
  needs = missingForBag(progress, bag)   // 复用现有函数
  forced = []
  for tag in needs (最多 2 个):
    若该区域池存在带此 tag 的物品 → 强制在「当前区域扇区 + 相邻扇区」内放置 1 个
  其余名额从各区域池均匀随机
```

- 保底点必须落在**已解锁**扇区内，且距离小人不超过半屏（避免玩家找不到）。
- 保底点在视觉上不做特殊标记——玩家看到的就是地上有个东西。
- 若 `needs` 中的标签在整个星球池里都不存在，说明配置有误，`distribute` 直接 `throw`，在开发期暴露。

必须写穷举测试：随机游玩 100,000 次，任何时刻地图上都存在可推进物品，通关率 100%。

### 6.4 合成台

- 双槽逻辑不变，`resolve()` 不变。
- 位置：手机在背包抽屉底部，网页在右侧栏。
- 槽位只接受背包内物品，不再从地面直接进槽。地上捡到的东西先进背包。

## 7. 技术架构

```
apps/web/src/
├── world/
│   ├── WorldCanvas.tsx      # PixiJS 挂载与生命周期
│   ├── layers.ts            # 背景 / 地面 / 物件 / 角色 / 特效 五层
│   ├── camera.ts            # 死区跟随 + 缩放钳制
│   ├── sprites.ts           # ItemIcon SVG → Sprite 的纹理生成
│   └── input.ts             # 点击地面 → 世界坐标 → 移动目标
├── screens/GameScreen.tsx   # 只保留 UI 层，世界交给 WorldCanvas
├── components/              # HUD / DialogueBar / BagDrawer / CraftSlots
└── styles/tokens.css        # 新增 --space / --planet / --planet-shade
```

**选型判断**
- PixiJS 8：WebGL 2D，手机 60fps 无压力，包体 gzip 后约 150KB。
- **不用 Three.js**：现有 55 个物品是 2D SVG，转 3D 全部作废；包体和移动端性能不可控。
- **不用纯 DOM**：小人在 DOM 里每帧改 transform，低端机会掉帧。
- React 只管 UI 层（HUD / 抽屉 / 对话），世界层完全在 Pixi 里，两者用 Zustand 单向同步。

**关键代码骨架**

```ts
// world.ts (game-core，纯函数，可测)
export interface PlacedItem {
  id: string;
  x: number; y: number;
  area: AreaId;
  spawnedDay: number;
}

export function distribute(
  progress: Progress,
  bag: Record<string, number>,

  rng: () => number,

```

```ts
// camera.ts
const DEAD_ZONE = 0.4;
export function follow(cam: Camera, target: Vec2, viewport: Size) {
  const dx = target.x - cam.x;
  const dy = target.y - cam.y;
  const limitX = (viewport.w * DEAD_ZONE) / cam.zoom / 2;
  const limitY = (viewport.h * DEAD_ZONE) / cam.zoom / 2;
  if (Math.abs(dx) > limitX) cam.x += dx - Math.sign(dx) * limitX;
  if (Math.abs(dy) > limitY) cam.y += dy - Math.sign(dy) * limitY;
  cam.x = clamp(cam.x, 80, 1360);
  cam.y = clamp(cam.y, 80, 1360);
}
```

## 10. 风险

| 风险 | 应对 |
|---|---|
| 星球太小显得空，太大走断腿 | 世界尺寸做成常量，M7 阶段用手机实机调，别在桌面上看 |
| 保底点太远，玩家找不到 | 限制生成距离 ≤ 半屏，并在目标提示条上给方向箭头（不标记具体位置） |
| Pixi 与 React 状态不同步 | 世界层只读 Zustand，写入只走 action，禁止 Pixi 直接改 store |
| 物品贴纸在星球上辨识度低 | 每个物品在角落加 1px 深色投影，必要时把贴纸底加白边（贴纸本来就是白边） |
| 手机发热 / 掉帧 | 关闭抗锯齿以外的效果，粒子数量上限 24，静止时不重绘 |
