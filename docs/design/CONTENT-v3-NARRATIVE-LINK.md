### 0.2 对 team-lead 倾向的评估

**倾向站得住，且应当升格为本批次的硬约束（不只是倾向）。** 理由见 §2.3 的四条论证。

补一条 team-lead 提到的倾向之外的**技术性理由**（这条比设计理由更硬）：

> **载体可消耗**（GDD R15，已定 🟢 保持现状）。日志载体是普通合成产物，会被别的配方吃掉，且「读到过」只记在 `ngPlus.readLogs` 集合里、不记背包快照。
> 后果：**如果把「读过 L8」做成 stay 结局的前置条件**，玩家只要在合成 L8 载体后、读到它之前，把它喂给了另一个配方，载体就消失了——而 `readLogs` 尚未记上，`readable` 态就永远不会出现。
> 玩家会卡在一个**「我明明合出来过」但永远读不到**的状态。
> 所以「联动只做追加、不做前置」不只是设计偏好，它同时是一条**防软锁的工程纪律**。

## 2 · 联动总原则

### 2.1 判据统一：`ngPlus.readLogs`，不用 `logsFound`

联动判据**一律**使用 **`ngPlus.readLogs`（跨周目已读集合）**，不用 `logsFound`（本周目载体记账）。理由：

| | `logsFound` | `ngPlus.readLogs` |
|---|---|---|
| 生命周期 | 单周目，二周目清零 | **跨周目保留**（C2 已实现） |
| 语义 | 本周目合出过哪些载体 | 这辈子读过哪些篇目 |
| 适合做结局联动？ | ❌ 二周目会突然失效 | ✅ 稳定 |

具体判据写法（可判定，无歧义）：

```
条件 C8  := ngPlus.readLogs.includes('L8')
条件 C3  := ngPlus.readLogs.includes('L3')
条件 C_read := ngPlus.readLogs.length >= 1
条件 C_stay := ngPlus.branchesHistory.includes('stay')
条件 C_cycle2 := ngPlus.cycle >= 2
```

**所有条件都可由存档字段直接判定，不含任何「感觉」成分**（如「玩家似乎理解了」）。

### 2.2 追加（additive），不替换（replacing）

**规则**：任何联动的结果，都是在基线文本之上**追加一段**，基线文本**一个字不动**。

- 基线 = 现在玩家在 `ENDINGS.stay` / `ENDING_LINES.stay` 里看到的全部内容；
- 追加 = 满足条件时，结局页在基线**下方**多出一块（独立标题 + 若干句），不插入、不替换、不改序。

这样做的直接后果就是 Q3 的**反向成立**：没读 L8 → 玩家看到的就是原来的基线，**完整、自洽、无缺口**。玩家不会知道自己错过了一块——**这是刻意的**：奖励不该以「缺口」的形式出现，否则就成了惩罚。

### 2.3 反向成立的四条论证（把倾向升格为约束）

1. **叙事完整性**：结局是这个游戏的**收束**，不是**奖品的兑奖券**。一个结局若需要另一段文本才能成立，它就不是结局，是**第二幕**。
2. **主题一致性**：L8 的核心是「我不要求你救谁」「选择权留给下一个」。若「读过 L8」决定了 stay 结局文本的完整性，那等于前任的选择**反过来决定了你结局的质量**——这与 L8 说的正相反。**前任把选择权留给了下一个，那他就不能同时是「下一个」的评分官。**
3. **工程防软锁**（见 §0.2）：载体可消耗 + 读取只记集合 → 前置式联动存在「合出后被吃掉 → 永远读不到 → 永远拿不到结局」的卡死路径。追加式没有这个风险。
4. **二周目一致性**：C2 的口径是「世界清零，你记得路」。若结局文本随阅读记录变化，二周目会拿到**和一周目不同的结局文本**——玩家会以为这是「新内容」，实际是「条件触发的旧文本」。追加式在二周目里同样触发（一周目读过 → 二周目仍成立），语义一致。

### 2.4 主题点一次（Q2 的具体落法）

「前任没替玩家做决定」这个主题在 v3 里的分布：

| 位置 | 现状 | 本批次动作 |
|---|---|---|
| L8 正文 | 已明确点出：「这卷带子是写给下一个的。**我不要求你救谁。**」「如果你读到这卷带子，说明你已经在星球上了。」 | 不动 |
| `ENDING_LINES.stay` 第 2 句 | 「**前人把钥匙留给了这颗星球**，你把它用上了。」——已从前任钥匙角度接过一次 | **不动** |
| stay 结局的**追加块**（新） | — | **在这里点第二次**：把「没替你做决定」从「钥匙」升级到「选择本身」 |

**为什么基线不再点**：基线第 2 句的「前人把钥匙留给了这颗星球」已经是一个**轻点**——它把「前任」的存在感放进结局，但没有任何**关于选择权**的断言。再加一句「他没替你做决定」会变成**说教**，而且会让基线在没有 L8 上下文时显得像在回应某个玩家不知道的东西。追加块才有上下文。

### 3.1 为什么不把 L8 挂到 leave

L8 里最像「劝玩家走」的一句是「**我们不是坠毁**」和「它唱只是症状，不是解药」——一个读完全部日志的玩家，很自然会得出「石头其实治不好，走是对的」。

**这正是不能做成 leave 联动的原因**：
- 如果 leave 在读过 L8 后获得一段「你走对了」的追加，**没读 L8 的玩家拿到的 leave 就成了「次等的 leave」**——反向成立被破坏；
- 更糟的是，它给玩家发了一个**道德许可**：读过日志 = 走 = 正确。不读 = 走 = 逃避。这是在用阅读记录给玩家的选择打分，与 L8 的主题正面冲突。

**结论**：leave 与 L8 **保持不联动**。L8 的力量在于它**不**给许可——它只是把一段真相摆在那儿，玩家自己解释。这与 stay 的处理方式不同（stay 那边是**追加一层观察**，不是**追加一层许可**）。

## 4 · 逐条联动规格

### 4.1 🟢 N-01 · stay 结局追加块「前任的最后一页」（v3.1）

| 项 | 内容 |
|---|---|
| **触发条件** | `C8` := `ngPlus.readLogs.includes('L8')` **且** 玩家本次进入的是 `stay` 结局 |
| **基线** | `ENDINGS.stay`（title / subtitle）+ `ENDING_LINES.stay` 4 句，**完全不变** |
| **追加形态** | 结局页在 4 句之后多出一个独立块：标题 + 3 句正文。有自己的视觉分隔（细横线 + 小标题），**不混入 4 句的段落流** |
| **反向成立** | ✅ 未读 L8 → 无此块，结局页与现在完全一致 |

**追加块标题（候选）**

- A：`前任的最后一页`
- B：`卷盘的最后一句`
- C：`他留给下一个的`

**推荐 A**：`前任的最后一页` —— 「前任」在游戏里已是固定称谓（GDD §6.3 全文自称不出现「前任」，是**日志之外的人**对这份记录的称呼；`log_b1` 的物品名也是「前任遗物」），用词与世界一致；「最后一页」呼应载体 `log_reel1`（一卷录音）与 L8「最后一卷录音」。

**追加块正文（定稿建议，3 句）**

```
'卷盘的最后一句是问石头还在唱吗，然后说别停。'
'你没停。'
'他说他不要求你救谁——这句话今天仍然成立，你也不是来救谁的。'
```

**逐句职责**

| 句 | 职责 | 承接 |
|---|---|---|
| 1 | **引 L8 的原话**（引用，不改写） | L8 倒数三段：「石头还在唱吗？」「如果它在唱，别停。」 |
| 2 | **把陈述变成事实**——两字句，落在玩家身上 | 「你没停」= 你留下来了。**不解释、不评价** |
| 3 | **点主题**（Q2 的落点）：前任没替玩家做决定 | L8「我不要求你救谁」+ 叙事者自己的判断（不是前任的） |

**语气自查**

- 一本正经的描述 + 反转收尾：第 1 句是陈述（他在录音里问石头），第 3 句是反转（他说不要求你救谁——可你也不是来救谁的）；
- 冷幽默：有，但不抖机灵。不说教、不煽情、无 emoji、无网络流行语；
- 第 2 句只有 4 个字，与 `ENDING_LINES.stay` 第 2 句「前人把钥匙留给了这颗星球，你把它用上了」形成**同频**（都是短陈述 + 一句补充），不显得突兀；
- **不剧透**：追加块出现的唯一前提是玩家**已经读完 L8 全文**，所以块内可以自由引用 L8 内容，不需要再藏。

**为什么不改 `ENDING_LINES.stay` 的第 2 句**：那 4 句是**基线**，任何玩家（读不读 L8）都看同一份。基线里塞只有读过 L8 才懂的话，是把「追加」偷偷做成了「替换」——反向成立就破了。

### 4.2 🟢 N-02 · birthday 结局追加块「他每天都跟它说话」（v3.1）

| 项 | 内容 |
|---|---|
| **触发条件** | `C8` := `ngPlus.readLogs.includes('L8')` **且** 结局为 `birthday` |
| **基线** | `ENDINGS.birthday` + `ENDING_LINES.birthday` 4 句，不变 |
| **追加形态** | 同样形态：分隔线 + 小标题 + 2 句 |

**追加块标题（推荐）**：`他每天早上跟它说话`

**追加块正文（定稿建议，2 句）**

```
'前任每天早上跟它说话，每天晚上把录音放给它听。'
'生日是他没有办过的一个。你办了。'
```

**逐句职责**

| 句 | 职责 |
|---|---|
| 1 | 引用 L8 原话（原文即「每天早上跟它说话，每天晚上把录音放给它听」） |
| 2 | 反转收尾：**他没办过的，你办了**——把「生日」从新事件变成「延续」 |

**为什么这条值得做**：GDD §6.4 衔接表已指出「生日支线是前任做过的事的延续」，但目前**这个延续只存在于设计文档里，玩家看不到**。这是 8 篇日志与既有内容之间**唯一一处「本来就在呼应、只是没说出来」**的衔接，且 L8 原文自带完美的一句。

**反向成立**：✅ 未读 L8 → 无此块；基线 4 句（仪式感、鼓掌、许愿）本身就是完整的生日结局。

**边界**：追加块**不**声称「前任没办过生日」是件悲伤的事，也不要提「他为什么不办」——那是 L8 之外的推测，超出文本能支撑的范围。

### 4.3 🟡 N-03 · leave 结局追加块「同一段航路，两个方向」（v3.2 候选）

| 项 | 内容 |
|---|---|
| **触发条件** | `C4` := `ngPlus.readLogs.includes('L4')` **且** 结局为 `leave` |
| **性质** | 🟡 排 v3.2。**内容待定**，此处只给判据与风险 |

**为什么它看起来成立**：L4 明确写了「我们不是掉下来的」「最后一段是 3 度」「图上标了『手动』」——玩家读完后，走出星球这个动作在叙事上确实被**重命名**了：不是「逃离坠毁」，而是「选了另一个方向」。

**为什么它排在 v3.2 而不是 v3.1（两条理由）**：

1. **Q1 的答案不能破例**：Q1 已定为「可见性不改、描述只做追加」。leave 的追加同样只能是追加——那它的**信息增量**就很小：告诉玩家「你走的方向和他相反」这件事，玩家其实已经能从 L4 推出来。追加块的价值密度明显低于 stay / birthday。
2. **更容易踩到「道德许可」的坑**（见 §3.1）：leave 的追加必须**极其克制**，写成任何近似「你比他聪明」/「你做了对的选择」的句子就毁了。宁可不写。

**若 v3.2 要做，建议的方向**（不写死，留给文案批次）：一句话，只陈述**事实并置**，不做评价——例如把「他压到 3 度」和「你起飞」并置，不加任何判断词。**任何带「聪明 / 勇敢 / 对 / 错」判断的写法一律否决。**

### 4.4 🟡 N-04 · 结局图鉴注脚「这一格相关的篇目」（v3.2）

| 项 | 内容 |
|---|---|
| **触发条件** | 结局格已解锁（`ngPlus.endings.includes(ending)`）**且** 至少 1 篇相关日志已读 |
| **形态** | 图鉴该格底部一行小字：`相关的记录：L6、L8`（只列**已读**的，不剧透未读的） |
| **落点** | C2 正在做图鉴 —— **这是 C2 的天然延伸，不建议另起批次** |
| **反向成立** | ✅ 没读过日志 → 无注脚行（而不是列 L6/L8 的空条目） |

**设计要点**：

- **只列已读的**。列出未读篇目的 id 或标题 = 剧透（违反 GDD §6.2.1 的口径）；
- 关联表**由 §3 的总表驱动**，不另写一份——避免两处映射表漂移（这正是 §1.1 那个「两张表都不是这张表」的教训）；
- 图鉴注脚是**纯装饰性**的：它给的是「这条线的素材在哪」，不是强度或成就。

**建议与 C2 合并**：C2 已经在做 5 格图鉴，顺手加一行注脚的成本远低于另开批次。**若 C2 已封版，则顺延到 v3.2。**

### 4.5 🟡 N-05 · 支线面板「他做过这一件」（v3.2）

| 项 | 内容 |
|---|---|
| **触发条件** | 支线为 `birthday` 或 `stay` **且** `C8` 成立 |
| **形态** | 支线面板该条下方一行小字：`前任做过类似的`（`birthday`）/ `前任在这儿待了二十一天`（`stay`） |
| **落点** | 支线面板渲染处（web 端） |

**为什么排 v3.2**：支线面板的 stay 条目文案（「前三条路是往远处走，这一条是往这儿扎」）是 `DIALOGUE.stage3` 的一部分，动它要跟 C2 之后的文案批次一起排。

## 5 · 建议保持不联动的组合（及理由）

这一节的价值在于**堵住后续反复讨论**。以下 8 条已逐条评估，建议**明确保持不联动**，除非有人能给出新的、文本上确实成立的钩子。

| # | 组合 | 不联动的理由 |
|---|---|---|
| **1** | **任何日志 → stay 的**可见性 / 支线门禁 | 可见性由 `buildDone` 决定是**玩法门禁**；让叙事阅读改玩法门禁会让「读日志」变成任务清单 → 违反 §2.3 第 2 条 |
| **2** | **L8 → leave 的追加** | 容易写成「你走对了」= **道德许可**；且会让没读 L8 的 leave 显得次等 → 破坏反向成立（§3.1） |
| **3** | **L7 → stay** | L7 揭示「石头是公司要带回去的货物」。挂到 stay 会暗示**知道真相才有资格留下**，把阅读记录变成资格线 → 违反 §2.3 第 2 条 |
| **4** | **L2 → leave** | L2「还剩不少燃料，够返程」很容易被读成「燃料够 → 你可以走」。挂上去等于给 leave 配一个**资源论证**，而 leave 的合法性不来自燃料 |
| **5** | **L1 → 任何结局** | L1 只交代「有过一个同伴、回声走了」。它不与任何**你的选择**构成因果；硬挂会让同伴线显得像某个结局的隐藏条件 |
| **6** | **L5 → 任何结局** | L5 的基调是「流程走完，人没了，石头也没了，而且每一步都合法」——这是**公司视角的绝望**。挂到任何结局都会把结局基调往下拽，且与结局的「你」无关 |
| **7** | **任何日志 → free** | free 是「没有目标了」——**空**是它的全部内容。加任何叙事块都会让 free 变成「有背景的空」；`ENDING_LINES.free` 现在那句「我建议什么都不做。难得。」的力量恰恰来自它前面没有铺垫 |
| **8** | **载体物品的 `desc` → 日志内容** | GDD §6.1 已定：内容只走日志面板，不进 `items.ts` 的 `desc`（≤40 字，只放钩子）。保持 |

**另外一个「不联动」的通用规则**：

> **不要让结局的追加块**泄露**未解锁结局**的暗示。例：stay 的追加块不能说「另一个选择是走」（那是 leave，玩家未必见过）。追加块只谈**这一条路**的事。

## 6 · 最小可行版本（v3.1）

### 6.1 范围

**只做 2 条**：N-01（stay 追加块）、N-02（birthday 追加块）。

**为什么是这 2 条**：

- 它们是 8 篇日志与既有内容之间**仅有的两处「原文自带完美承接句」**（L8 的「每天早上跟它说话」直接呼应 birthday；L8 的「别停」直接呼应 stay）——不需要新写剧情，只需要把 L8 已经写好的句子在对的时刻递出去；

### 6.3 建议的实现形状（仅示意，不落码）

```
// game-core/src/dialogue.ts（示意）
export const ENDING_EXTRAS = {
  stay: [
    {
      title: '前任的最后一页',
      lines: [
        '卷盘的最后一句是问石头还在唱吗，然后说别停。',
        '你没停。',
        '他说他不要求你救谁——这句话今天仍然成立，你也不是来救谁的。',
      ],
      requires: (readLogs: readonly string[]) => readLogs.includes('L8'),
    },
  ],
  birthday: [
    {
      title: '他每天早上跟它说话',
      lines: [
        '前任每天早上跟它说话，每天晚上把录音放给它听。',
        '生日是他没有办过的一个。你办了。',
      ],
      requires: (readLogs: readonly string[]) => readLogs.includes('L8'),
    },
  ],
} as const;
```

要点：

- `requires` 收 **`readLogs` 数组**而不是整个 `SaveState`——纯函数、易测、不碰存档结构；
- 追加块**与结局 id 一一对应**，不与日志 id 一一对应（一个结局可能有多条追加、来自不同日志）；
- `ENDING_EXTRAS` 与 `ENDING_LINES` **物理分离**，避免改基线时误伤追加块。

### 6.4 验收标准（可判定）

| # | 验收项 | 判定方式 |
|---|---|---|
| 1 | 读过 L8 的存档进 `stay` 结局页 → 基线 4 句**原样** + 追加块出现 | 浏览器实测 / 单元测试 |
| 2 | **未读** L8 的存档进 `stay` 结局页 → 只有基线 4 句，**无追加块**，页面无空标题、无占位、无「？？？」 | 单测 + 实测 |
| 3 | 同上，`birthday` | 同上 |
| 4 | `leave` / `teashop` / `free` 结局页**在任何存档状态下都无追加块** | 单测（4 种结局 × {读过 L8, 没读过}） |
| 5 | `readLogs` 缺失 / 脏数据（老存档、手改存档）→ 追加块判定为 false，**不报错** | 归一化单测 |
| 6 | 二周目（`cycle=2`）里，一周目读过 L8 → 追加块**仍然出现** | 单测 |
| 7 | `save.ngPlus.readLogs` 含 L8 但 `logsFound` 为空（二周目载体已清零）→ 追加块**仍然出现** | 单测（这条专门防「用错字段」） |
| 8 | 本批次**未新增任何存档字段**，`schemaVersion` 未 bump | `git diff` 人工核对 + 存档契约测试 |

第 7 条是本批次最容易踩的坑：判据若误用 `logsFound`（本周目载体记账），二周目里追加块会**整块消失**——而玩家一周目明明读过。**验收必须显式覆盖这一条。**

## 10 · 附录 · 追加块文本一览（供文案评审）

### N-01 · stay（条件：`readLogs` 含 L8）
