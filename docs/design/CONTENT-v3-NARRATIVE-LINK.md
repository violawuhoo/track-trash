### 0.2 对 team-lead 倾向的评估

**倾向站得住，且应当升格为本批次的硬约束（不只是倾向）。** 理由见 §2.3 的四条论证。

补一条 team-lead 提到的倾向之外的**技术性理由**（这条比设计理由更硬）：

> **载体可消耗**（GDD R15，已定 🟢 保持现状）。日志载体是普通合成产物，可以被别的配方吃掉。
> 后果：**如果把「读过 L8」做成 stay 结局的前置条件**（即要求玩家真的点开过正文），玩家只要在合成 L8 载体后、还没去读它之前，把它喂给了另一个配方，载体就消失了——正文也就永远读不到，`readLogs` 永远不会记上 L8。
> 玩家会卡在一个**「我明明合出来过、但永远没机会读」**的状态。
> 所以「联动只做追加、不做前置」不只是设计偏好，它同时是一条**防软锁的工程纪律**。
> 注意这条论证在「点开正文才记」的记账口径下**更成立**：连「合出过」都不保证玩家读过——「合出过」只是「有机会读」，「读过」才是「读到了」。

### 1.3 GDD §6.4 两处内容级错误（本批次一并修正认知，不改 GDD 原文）

这两条不影响任何代码，但会影响「联动写在哪」的判断，故在此纠正：

**错误 1：§6.4 衔接表把「回声」归给了 L3，实际在 L1。**

> §6.4 原文：`| note 外星留言条「你们也迷路了吗」 | L3「另一个的字比我圆，像在描」→ … |`
>
> 实际：`logs.ts` **L1** 第 4 段：「这本书是两个人写的。我负责里面的机械部分，另一部分归对接员「回声」。**他的字比我的圆**，一笔一画都像在描。」
> **L3 里没有这句话**（L3 讲的是值班日常、石头唱了 14 遍、第 12 天回声最后回话）。

**错误 2：§6.4 拼合点 P1 说「读到 L2 揭示同伴」，但同伴在 L1 已经揭示。**

> §6.4 原文：`| P1 | 读到 L2 | 「船上原本有两个人，其中一个后来自己走了」 | … |`
>
> 实际：**L1** 末段已写「船上原本两个人。我在这儿。」「第 12 天以后回声没有再回话。记录上写的是「外部联络中止」，我倾向于写「没人回了」。」
> L1 是**没有 `puzzle` 字段**的 8 篇之一（`puzzle` 只挂在 L2/L4/L6/L8 上），因为 puzzle 的定位是「合并出的新结论」，而 L1 是**第一手信息**、不是合并结论。
>
> **⚠️ 本节此前的推理方向是反的，已于 2026-10-22 修正。** 旧版本写的是：
> 「**『有同伴』是 L1 给的，『同伴自己走了』这个新结论才是 L2 给的**——P1 的措辞（「其中**一个后来自己走了**」）其实正是 L2 的 puzzle 原文，§6.4 把触发点标早了一篇。」
> **这段推理已被证伪，不成立。** 正确结论是：
> - **「一个自己走了」这个结论在 L1 就已经可以推出来**，不需要 L2。L1 里给了三条互相咬合的线索：①「船上原本两个人。我在这儿。」（有两个人，且说话人是留下的那个）②「第 12 天以后回声没有再回话……记录上写的是『外部联络中止』，我倾向于写『**没人回了**』」（另一个人走了）③「**如果你读到这段，说明我是那个没走的。**」（说话人确认自己没走）。
> - 三条合起来，「其中**一个**（不是我）**后来自己走了**」这个结论玩家**读完 L1 就能自己说出来**。
> - 因此 L2 的 puzzle 原文「船上原本有两个人，其中一个后来自己走了」**不是新结论，是玩家已知信息的复述**——它不构成拼合点。
> - 真正给出「回声带着公司最后一道指令**自己走了**」这个完整因果的是 **L8**（「第 12 天，回声带着公司最后一道指令自己走了，指令内容是『带它回来』。我把回声送走的。」）。**这条因果 L1 没有给**，所以它是 L8 的新信息——但它属于 L8 正文，不是拼合点。
>

## 2 · 联动总原则

### 2.1 判据统一：`ngPlus.readLogs`，不用 `logsFound`

联动判据**一律**使用 **`ngPlus.readLogs`（跨周目「读过」集合）**，不用 `logsFound`（本周目载体记账）。理由：

#### 两字段职责对照（**判据只能用 `readLogs`**）

| | `logsFound` | `ngPlus.readLogs` |
|---|---|---|
| 语义 | 「**本周目合出过哪些载体**」 | 「**这辈子读过哪些篇目**」 |
| 写入方 | core `craft()`（合成出载体时） | **web 端日志面板「点开正文」动作** → core `recordReadLog` |
| 生命周期 | **单周目**，`startNextCycle` 里被清零 | **跨周目保留**（C2 G1「你记得路」） |
| 载体被消耗时 | 不受影响（记的是 id 集合） | 不受影响（记的是 id 集合） |
| 适合做结局联动？ | ❌ 二周目会静默失效 | ✅ 稳定 |

> **判据只能用 `readLogs`**，因为 `logsFound` 在 `startNextCycle` 里会被清零——**用它做判据会让追加块在二周目里静默失效**（玩家一周目明明读过，追加块却不出现）。这条是准入清单第 7 条的来源。

> **⚠️ 语义精确化（**措辞终稿**，2026-10-21 team-lead 二次核实）**：`ngPlus.readLogs` 的准确语义是「**玩家点开过这篇日志的正文**」，**不是「合出过载体」**。
> 依据：core 的 `craft()` **只写本周目的 `logsFound`，不写 `readLogs`**——`state.ts:216-221` 的注释原话：「这里**不写** `ngPlus.readLogs`：那是『这辈子读过哪些篇目』，由玩家在日志面板里点开正文时才记。**『拿到载体』与『读过』是两件事，别混。**」core 的 `alreadyRead()` / `readableLogs()`（`logs.ts:302/312`）也是这个语义。
> **因此本批次的触发条件一律写作「读过 L8」。**
> **对设计结论的影响：没有，而且更强**——反向成立从「没**获得过载体**时成立」升级为「没**读过**时成立」，门槛更严、更贴近玩家的真实状态（§0.2 的软锁论证在这个口径下更成立）。变的是**措辞的准确性**——写错会导致测试用错前置（见 §6.4-1/2/7/9）。

具体判据写法（可判定，无歧义）：

```
条件 C8   := ngPlus.readLogs.includes('L8')      // 读过 L8（点开过正文）
条件 C4   := ngPlus.readLogs.includes('L4')      // 读过 L4
条件 C3   := ngPlus.readLogs.includes('L3')      // 读过 L3
条件 C_read := ngPlus.readLogs.length >= 1       // 至少读过 1 篇
条件 C_all  := ngPlus.readLogs.length >= 8       // 8 篇全部读过
条件 C_stay := ngPlus.branchesHistory.includes('stay')
条件 C_cycle2 := ngPlus.cycle >= 2
```

**所有条件都可由存档字段直接判定，不含任何「感觉」成分**（如「玩家似乎理解了」）。

### 2.2 追加（additive），不替换（replacing）

**规则**：任何联动的结果，都是在基线文本之上**追加一段**，基线文本**一个字不动**。

- 基线 = 现在玩家在 `ENDINGS.stay` / `ENDING_LINES.stay` 里看到的全部内容；
- 追加 = 满足条件时，结局页在基线**下方**多出一块（独立标题 + 若干句），不插入、不替换、不改序。

这样做的直接后果就是 Q3 的**反向成立**：没获得 L8 载体 → 玩家看到的就是原来的基线，**完整、自洽、无缺口**。玩家不会知道自己错过了一块——**这是刻意的**：奖励不该以「缺口」的形式出现，否则就成了惩罚。

### 2.3 反向成立的四条论证（**已拍板升格为硬约束**）

1. **叙事完整性**：结局是这个游戏的**收束**，不是**奖品的兑奖券**。一个结局若需要另一段文本才能成立，它就不是结局，是**第二幕**。
2. **主题一致性**：L8 的核心是「我不要求你救谁」「选择权留给下一个」。若「读过 L8」决定了 stay 结局文本的完整性，那等于前任的选择**反过来决定了你结局的质量**——这与 L8 说的正相反。**前任把选择权留给了下一个，那他就不能同时是「下一个」的评分官。**
3. **工程防软锁**（见 §0.2）：载体可消耗 + 前置联动要求玩家真的读到正文 → 若做成前置条件，存在「合出后被吃掉 → 永远读不到 → 永远拿不到结局」的卡死路径。**追加式在载体被消耗这条路径上依然成立**（判据是 `readLogs`，载体被消耗不影响已读记录），从结构上消掉了它。
4. **二周目一致性**：C2 的口径是「世界清零，你记得路」。若结局文本随阅读记录变化，二周目会拿到**和一周目不同的结局文本**——玩家会以为这是「新内容」，实际是「条件触发的旧文本」。追加式在二周目里同样触发（读过 → 二周目仍成立），语义一致。

### 2.4 主题点一次（Q2 的具体落法）

「前任没替玩家做决定」这个主题在 v3 里的分布：

| 位置 | 现状 | 本批次动作 |
|---|---|---|
| L8 正文 | 已明确点出：「这卷带子是写给下一个的。**我不要求你救谁。**」「如果你读到这卷带子，说明你已经在星球上了。」 | 不动 |
| `ENDING_LINES.stay` 第 2 句 | 「**前人把钥匙留给了这颗星球**，你把它用上了。」——已从前任钥匙角度接过一次 | **不动** |
| stay 结局的**追加块**（新） | — | **在这里点第二次**：把「没替你做决定」从「钥匙」升级到「选择本身」 |

**为什么基线不再点**：基线第 2 句的「前人把钥匙留给了这颗星球」已经是一个**轻点**——它把「前任」的存在感放进结局，但没有任何**关于选择权**的断言。再加一句「他没替你做决定」会变成**说教**，而且会让基线在没有 L8 上下文时显得像在回应某个玩家不知道的东西。追加块才有上下文。

### 2.5 联动准入清单（**7 条 · 机械判定**）

> **用途**：任何新联动提案，**先拿这 7 条过一遍，不通过直接不立项，不用再讨论。**
> 这套清单是从 §4.3 / §3.1 的具体否决案例里抽出来的**判定标准**，不是偏好。它能机械判定，因此比逐条讨论省事得多。

**一条联动要同时满足以下全部条件，才可立项**：

| # | 条件 | 判定方式 |
|---|---|---|
| **1** | **判据可由存档字段直接判定，不含「感觉」** | 写不出一个只用 `SaveState` 字段的布尔表达式（如 `ngPlus.readLogs.includes('L8')`）→ 不通过。判据里出现「玩家似乎理解了」「玩家大概想要」→ 不通过 |
| **2** | **追加块不泄露未解锁的结局 / 支线的存在** | 追加块里若出现玩家尚未见过的结局 / 支线名或暗示 → 不通过。例：stay 的追加块不能说「另一个选择是走」 |
| **3** | **追加块不改变该结局的可见性、获取条件、难度** | 只要它动了 `buildDone`、支线解锁条件、槽位判定、结局页出现时机中的任何一项 → 不通过。**叙事不碰玩法门禁** |
| **4** | **追加块不形成许可** | 追加块不能被读成「知道 X 才有资格 Y」「读过 = 走 = 正确」「你比他聪明/勇敢」。**注**：**先例不自动成立，每条独立判定**——L8→leave 被否，不代表 L4→leave 可以放行（见 §4.3、§5.1） |
| **5** | **不点名未获篇目、不出现篇目计数**（逐篇联动时） | 追加块里出现未获得篇目的 id / 标题，或出现「N 篇」这类数字 → 不通过。反向检查：追加块里的每一句引用，都必须能在**触发它的那一篇**原文里找到出处 |
| **6** | **基线台词一字不动，追加块物理分离** | `ENDING_LINES` / `ENDINGS` 不改一个字；追加块用**独立的数据结构与独立的 UI 块**承载（`ENDING_EXTRAS` vs `ENDING_LINES`，见 §6.3） |
| **7** | **判据用 `ngPlus.readLogs`（跨周目「读过」），不用 `logsFound`（单周目「合出过载体」）** | 判据里出现 `logsFound` → 不通过。理由见 §2.1 的两字段职责对照与 §6.4-7 |

**用法补充**：

- **7 条是「与」不是「或」**——任何一条不通过，直接不立项，**不再进入讨论**。
- 通过 7 条之后，仍需过一道**人工判断**：追加块是否**至少带来一点新东西**（不是「玩家已经知道的事实」的复述）。这一条无法机械化，但有现成的反例可参照——N-07 就是因为「零信息增量」被关闭的（§4.7 / §5.1）。
- **第 4 条的注脚是这份清单里最容易被忽略、也最重要的一句**：先例不自动成立。每一条新提案都要自己过一遍，不许援引「上次那条是怎么做的」。

### 3.1 为什么不把 L8 挂到 leave

L8 里最像「劝玩家走」的一句是「**我们不是坠毁**」和「它唱只是症状，不是解药」——一个读完全部日志的玩家，很自然会得出「石头其实治不好，走是对的」。

**这正是不能做成 leave 联动的原因**：
- 如果 leave 在获得 L8 载体后获得一段「你走对了」的追加，**没获得 L8 载体的玩家拿到的 leave 就成了「次等的 leave」**——反向成立被破坏；
- 更糟的是，它给玩家发了一个**道德许可**：读过日志 = 走 = 正确。没读过 = 走 = 逃避。这是在用阅读记录给玩家的选择打分，与 L8 的主题正面冲突。

**结论（已拍板，硬约束）**：leave 与 L8 **保持不联动**。L8 的力量在于它**不**给许可——它只是把一段真相摆在那儿，玩家自己解释。这与 stay 的处理方式不同（stay 那边是**追加一层观察**，不是**追加一层许可**）。

## 4 · 逐条联动规格

### 4.1 🟢 N-01 · stay 结局追加块「前任的最后一页」（v3.1）

| 项 | 内容 |
|---|---|
| **触发条件** | `C8` := `ngPlus.readLogs.includes('L8')` **且** 玩家本次进入的是 `stay` 结局 |
| **基线** | `ENDINGS.stay`（title / subtitle）+ `ENDING_LINES.stay` 4 句，**完全不变** |
| **追加形态** | 结局页在 4 句之后多出一个独立块：标题 + 3 句正文。有自己的视觉分隔（细横线 + 小标题），**不混入 4 句的段落流** |
| **反向成立** | ✅ 未获得 L8 载体 → 无此块，结局页与现在完全一致 |

**追加块标题（**已拍板**）**

- A：`前任的最后一页` ← **✅ 已采纳**
- B：`卷盘的最后一句`
- C：`他留给下一个的`

**采纳 A 的理由**：「前任」在游戏里已是固定称谓（GDD §6.3 全文自称不出现「前任」，是**日志之外的人**对这份记录的称呼；`log_b1` 的物品名也是「前任遗物」），用词与世界一致；「最后一页」呼应载体 `log_reel1`（一卷录音）与 L8「最后一卷录音」。

**追加块正文（**已定稿**，3 句）**

```
'卷盘的最后一句是问石头还在唱吗，然后说别停。'
'你没停。'
'他说他不要求你救谁——这句话今天仍然成立，你也不是来救谁的。'
```

**逐句职责**

| 句 | 职责 | 承接 |
|---|---|---|
| 1 | **引 L8 的原话**（引用，不改写） | L8 倒数三段：「石头还在唱吗？」「如果它在唱，别停。」 |
| 2 | **把陈述变成事实**——两字句，落在玩家身上 | 「你没停」= 你留下来了。**不解释、不评价** |
| 3 | **点主题**（Q2 的落点）：前任没替玩家做决定 | L8「我不要求你救谁」+ 叙事者自己的判断（不是前任的） |

**语气自查**

- 一本正经的描述 + 反转收尾：第 1 句是陈述（他在录音里问石头），第 3 句是反转（他说不要求你救谁——可你也不是来救谁的）；
- 冷幽默：有，但不抖机灵。不说教、不煽情、无 emoji、无网络流行语；
- 第 2 句只有 4 个字，与 `ENDING_LINES.stay` 第 2 句「前人把钥匙留给了这颗星球，你把它用上了」形成**同频**（都是短陈述 + 一句补充），不显得突兀；

### 4.7 🔴 N-07 · `free` 结局的**计数式**追加块（**已拍板关闭 · 不进 v3.2**）

> **提出方式**：team-lead 提出——`free` 的语义是「没有目标了」，而 free 玩家大概率是「什么都经历了但什么都没留下」的人；是否值得给 free 一个**不带具体日志依赖**的通用追加块（例如按 `readLogs.length` 分档）。
> **与 §5 第 7 条的关系**：不冲突。§5 第 7 条禁的是**逐篇**联动（L1→free、L8→free……），禁不掉**计数式**联动。
> **拍板（2026-10-21 · team-lead）：关闭，不立项。**

#### 关闭理由：**零信息增量 + 排版成本 + 稀释核心语义 = 不做**

把四条约束（C-1 ~ C-4）与判据放在一起算一遍，结果是：

| 约束 | 后果 |
|---|---|
| C-1 不点名任何一篇 | 追加块无法引用任何具体内容 |
| C-2 不出现「N 篇」数字 | 追加块无法表达数量 |
| C-3 只分 1 档 | 追加块**不区分任何玩家** |
| 判据只判 `readLogs.length >= 1` | 触发条件几乎没有筛选力 |

**四条合起来的结果**：所有满足条件的玩家看到**完全相同的一句话**，而这句话表达的内容（「你捡了些东西，它们在背包里，没人规定要拿去干什么」）**是玩家已经知道的事实**。

- 它**不区分任何玩家**（这是 C-3 想要的）；
- 它**也不传达任何新信息**（这是它没预料到的致命处）；
- 但代价是实的：free 基线 3 句变 5 句、**页面呼吸感改变**、「空」的核心语义被稀释（风险 L10），还要真机校准排版。

> **零信息增量 + 排版成本 + 稀释核心语义 = 不做。** 这不是「暂缓」，是**关闭**。

**保留价值**：四条约束（C-1 ~ C-4）与「判据退化后必然零信息增量」这条推理，**作为判定标准本身保留**——它是这类「泛化型追加块」的通用筛子。将来有人再提类似点子，直接拿它当筛子过一遍即可。**但这条具体实现不进 v3.2。**

#### 归档（原方案，保留供查阅，不实现）

**原四条约束**：

| # | 约束 | 理由 |
|---|---|---|
| **C-1** | **不出现具体篇目 id、不点名任何一篇** | 一旦点名（「你读过 L4 和 L8」），它就退化成逐篇联动，§5 第 7 条立刻被违反；也变成一份**成绩单** |
| **C-2** | **不出现「N 篇」这种数字** | free 的全部力量是「没有目标 / 没有数字」。一旦出现计数，free 就变成了「你的收集进度」——这是**把 free 变成任务清单**，与它的语义正面冲突 |
| **C-3** | **只分 1–2 档，且档位之间不构成优劣** | 分档的唯一目的是「让不同玩家看到不同的一句话」，不是为了给玩家评级。任何「读得越多、这句越华」的梯度都是评分 → 违反 §2.3 第 2 条 |
| **C-4** | **不改变 `ENDING_LINES.free` 基线一个字** | 与 N-01 / N-02 同一纪律 |

**原判据**：`C_free_any := ngPlus.readLogs.length >= 1`（原建议只做 1 档；`C_free_all := length >= 8` 未采用）。

**原文案草案（已作废）**：标题「你也带了些东西」／「你把该捡的都捡了，该合的都合了，然后什么也没选。」+「东西还在背包里。没人规定它们要拿去干什么。」

**原工程量评估**：比 N-01 / N-02 略大（多一个档位判断 + 一次措辞校对）。**关闭后此项成本归零。**

**时机（已拍板）**：**排在 C2 落地之后、紧接着的下一个批次**。理由见 §0.4——判据字段 `ngPlus.readLogs` 是 C2 新增的，`ngPlus` 对象容器形态与 web 侧读写路径在 C2 收尾前都还没定型。

- 它们**互不依赖**，可以分两个 commit，也可以一次做完；
- 它们的追加块**共享同一套 UI 形态**（分隔线 + 小标题 + 正文），所以 UI 成本是 1 份而不是 2 份。

### 6.3 建议的实现形状（仅示意，不落码）

```
// game-core/src/dialogue.ts（示意）
export const ENDING_EXTRAS = {
  stay: [
    {
      title: '前任的最后一页',
      lines: [
        '卷盘的最后一句是问石头还在唱吗，然后说别停。',
        '你没停。',
        '他说他不要求你救谁——这句话今天仍然成立，你也不是来救谁的。',
      ],
      requires: (readLogs: readonly string[]) => readLogs.includes('L8'),
    },
  ],
  birthday: [
    {
      title: '他每天早上跟它说话',
      lines: [
        '前任每天早上跟它说话，每天晚上把录音放给它听。',
        '生日是他没有办过的一个。你办了。',
      ],
      requires: (readLogs: readonly string[]) => readLogs.includes('L8'),
    },
  ],
} as const;
```

要点：

- `requires` 收 **`readLogs` 数组**而不是整个 `SaveState`——纯函数、易测、不碰存档结构；
- 追加块**与结局 id 一一对应**，不与日志 id 一一对应（一个结局可能有多条追加、来自不同日志）；
- `ENDING_EXTRAS` 与 `ENDING_LINES` **物理分离**，避免改基线时误伤追加块。

### 6.4 验收标准（可判定）

> **措辞前提（**终稿**，2026-10-21 修正）**：`readLogs` 的语义是「**玩家点开过这篇日志的正文**」（§2.1），**不是「合出过载体」**。下表统一按「**读过 L8**」写，测试前置也按此构造（合成出 `log_reel1` → 打开日志面板点开该篇正文 → `readLogs` 写入 L8）。

| # | 验收项 | 判定方式 |
|---|---|---|
| 1 | `readLogs` 含 L8（**读过 L8**）的存档进 `stay` 结局页 → 基线 4 句**原样** + 追加块出现 | 浏览器实测 / 单元测试 |
| 2 | **`readLogs` 不含 L8（没读过）** 的存档进 `stay` 结局页 → 只有基线 4 句，**无追加块**，页面无空标题、无占位、无「？？？」 | 单测 + 实测 |
| 3 | 同上，`birthday` | 同上 |
| 4 | `leave` / `teashop` / `free` 结局页**在任何存档状态下都无追加块**（v3.1 范围内） | 单测（4 种结局 × {`readLogs` 含 L8, 不含 L8}） |
| 5 | `readLogs` 缺失 / 脏数据（老存档、手改存档）→ 追加块判定为 false，**不报错** | 归一化单测 |
| 6 | 二周目（`cycle=2`）里，一周目**读过** L8 → 追加块**仍然出现** | 单测 |
| 7 | `save.ngPlus.readLogs` 含 L8 但 `logsFound` 为空（二周目载体已清零）→ 追加块**仍然出现** | 单测（这条专门防「用错字段」） |
| 8 | 本批次**未新增任何存档字段**，`schemaVersion` 未 bump | `git diff` 人工核对 + 存档契约测试 |
| 9 | **载体被消耗的情形**：**读过 L8** → 把载体喂给别的配方消耗掉 → `readLogs` 仍含 L8 → 追加块**仍然出现** | 单测（这条守的是**两字段职责分离**，见下方说明） |

第 7 条与第 9 条是本批次最容易踩的两个坑：

- **第 7 条**：判据若误用 `logsFound`（本周目载体记账），二周目里追加块会**整块消失**——而玩家一周目明明读过。**验收必须显式覆盖。**
- **第 9 条**：判据若写成「载体还在背包里」或「合出过载体」，那条「读完就被消耗」的路径就会让追加块消失。
  **这条测试要守的正是两字段的职责分离**：
  - 载体被消耗，只影响 **`logsFound`（本周目，载体记账）**——它记的是「本周目合出过哪些载体」，载体没了这个记录**不撤销**（合出一次就记上）；
  - 载体被消耗，**不影响 `readLogs`（跨周目，已读记账）**——玩家**已经读过**这件事，不会因为物品被消耗而消失。
  两条记录互不覆盖、互不回滚，追加块挂在 `readLogs` 上，因此**不受载体存亡影响**。这就是追加式相对前置式的全部优势所在。
