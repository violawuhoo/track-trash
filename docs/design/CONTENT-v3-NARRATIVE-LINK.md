### 0.2 对 team-lead 倾向的评估

**倾向站得住，且应当升格为本批次的硬约束（不只是倾向）。** 理由见 §2.3 的四条论证。

补一条 team-lead 提到的倾向之外的**技术性理由**（这条比设计理由更硬）：

> **载体可消耗**（GDD R15，已定 🟢 保持现状）。日志载体是普通合成产物，可以被别的配方吃掉，而 `ngPlus.readLogs` 记的是**日志 id 集合**、不记背包快照。
> 后果：**如果把「获得 L8 载体」做成 stay 结局的前置条件**，玩家只要在合成 L8 载体后、还没去读它之前，把它喂给了另一个配方，载体就消失了——而 `readLogs` 在 `craft()` 当场就已经记上了（`state.ts:226-228`，合出即记），所以追加块**仍然**会出现。
> 换句话说：**追加式在载体被消耗这条路径上依然成立**，这正是它比前置式更稳的地方。
> 反过来说，如果做成「必须读到全文」的前置条件，就会出现**「我明明合出来过、但面板上永远读不到」**的软锁路径——追加式从结构上消掉了它。

## 2 · 联动总原则

### 2.1 判据统一：`ngPlus.readLogs`，不用 `logsFound`

联动判据**一律**使用 **`ngPlus.readLogs`（跨周目「获得过载体」集合）**，不用 `logsFound`（本周目载体记账）。理由：

| | `logsFound` | `ngPlus.readLogs` |
|---|---|---|
| 生命周期 | 单周目，二周目清零 | **跨周目保留**（C2 已实现） |
| 语义 | 本周目**合出过**哪些载体 | 这辈子**获得过载体**的篇目 |
| 适合做结局联动？ | ❌ 二周目会突然失效 | ✅ 稳定 |

> **⚠️ 语义精确化（2026-10-21 team-lead 核实修正）**：`ngPlus.readLogs` 的准确语义是「**合出过载体**」，**不是「打开面板读过全文」**。
> 依据：`state.ts:226-228` 在 `craft()` 里一旦产出载体就 `recordReadLog(next.ngPlus, logId)`——**合出即记，不等玩家打开日志面板**。core 的 `alreadyRead()` / `readableLogs()`（`logs.ts:302/312`）也是这个语义。
> **因此本批次的触发条件一律写作「获得过 L8 载体」，不写「读过 L8 / 读完 L8」。** 两者在实现上等价，在**验收标准的写法**上不等价——写错会导致测试用错前置（见 §6.4-1/2/7）。
> **对设计结论的影响：没有。** 触发条件宽一点（合出即算）比严一点更安全，也更符合防软锁初衷（§0.2）。

具体判据写法（可判定，无歧义）：

```
条件 C8   := ngPlus.readLogs.includes('L8')      // 获得过 L8 载体（合出即记）
条件 C4   := ngPlus.readLogs.includes('L4')      // 获得过 L4 载体
条件 C3   := ngPlus.readLogs.includes('L3')      // 获得过 L3 载体
条件 C_read := ngPlus.readLogs.length >= 1       // 至少获得过 1 篇载体
条件 C_all  := ngPlus.readLogs.length >= 8       // 8 篇载体全部获得过
条件 C_stay := ngPlus.branchesHistory.includes('stay')
条件 C_cycle2 := ngPlus.cycle >= 2
```

**所有条件都可由存档字段直接判定，不含任何「感觉」成分**（如「玩家似乎理解了」）。

### 2.2 追加（additive），不替换（replacing）

**规则**：任何联动的结果，都是在基线文本之上**追加一段**，基线文本**一个字不动**。

- 基线 = 现在玩家在 `ENDINGS.stay` / `ENDING_LINES.stay` 里看到的全部内容；
- 追加 = 满足条件时，结局页在基线**下方**多出一块（独立标题 + 若干句），不插入、不替换、不改序。

这样做的直接后果就是 Q3 的**反向成立**：没获得 L8 载体 → 玩家看到的就是原来的基线，**完整、自洽、无缺口**。玩家不会知道自己错过了一块——**这是刻意的**：奖励不该以「缺口」的形式出现，否则就成了惩罚。

### 2.3 反向成立的四条论证（**已拍板升格为硬约束**）

1. **叙事完整性**：结局是这个游戏的**收束**，不是**奖品的兑奖券**。一个结局若需要另一段文本才能成立，它就不是结局，是**第二幕**。
2. **主题一致性**：L8 的核心是「我不要求你救谁」「选择权留给下一个」。若「获得 L8 载体」决定了 stay 结局文本的完整性，那等于前任的选择**反过来决定了你结局的质量**——这与 L8 说的正相反。**前任把选择权留给了下一个，那他就不能同时是「下一个」的评分官。**
3. **工程防软锁**（见 §0.2）：载体可消耗 + 记账只记集合 → 若做成「必须读到全文」的前置联动，存在「合出后被吃掉 → 永远读不到 → 永远拿不到结局」的卡死路径。**追加式在载体被消耗这条路径上依然成立**（`readLogs` 在 `craft()` 当场就记上了），从结构上消掉了它。
4. **二周目一致性**：C2 的口径是「世界清零，你记得路」。若结局文本随获得记录变化，二周目会拿到**和一周目不同的结局文本**——玩家会以为这是「新内容」，实际是「条件触发的旧文本」。追加式在二周目里同样触发（获得过 → 二周目仍成立），语义一致。

### 2.4 主题点一次（Q2 的具体落法）

### 3.1 为什么不把 L8 挂到 leave

L8 里最像「劝玩家走」的一句是「**我们不是坠毁**」和「它唱只是症状，不是解药」——一个读完全部日志的玩家，很自然会得出「石头其实治不好，走是对的」。

**这正是不能做成 leave 联动的原因**：
- 如果 leave 在获得 L8 载体后获得一段「你走对了」的追加，**没获得 L8 载体的玩家拿到的 leave 就成了「次等的 leave」**——反向成立被破坏；
- 更糟的是，它给玩家发了一个**道德许可**：获得过日志 = 走 = 正确。没获得 = 走 = 逃避。这是在用获得的记录给玩家的选择打分，与 L8 的主题正面冲突。

**结论（已拍板，硬约束）**：leave 与 L8 **保持不联动**。L8 的力量在于它**不**给许可——它只是把一段真相摆在那儿，玩家自己解释。这与 stay 的处理方式不同（stay 那边是**追加一层观察**，不是**追加一层许可**）。

### 4.1 🟢 N-01 · stay 结局追加块「前任的最后一页」（v3.1）

| 项 | 内容 |
|---|---|
| **触发条件** | `C8` := `ngPlus.readLogs.includes('L8')` **且** 玩家本次进入的是 `stay` 结局 |
| **基线** | `ENDINGS.stay`（title / subtitle）+ `ENDING_LINES.stay` 4 句，**完全不变** |
| **追加形态** | 结局页在 4 句之后多出一个独立块：标题 + 3 句正文。有自己的视觉分隔（细横线 + 小标题），**不混入 4 句的段落流** |
| **反向成立** | ✅ 未获得 L8 载体 → 无此块，结局页与现在完全一致 |

**追加块标题（**已拍板**）**

- A：`前任的最后一页` ← **✅ 已采纳**
- B：`卷盘的最后一句`
- C：`他留给下一个的`

**采纳 A 的理由**：「前任」在游戏里已是固定称谓（GDD §6.3 全文自称不出现「前任」，是**日志之外的人**对这份记录的称呼；`log_b1` 的物品名也是「前任遗物」），用词与世界一致；「最后一页」呼应载体 `log_reel1`（一卷录音）与 L8「最后一卷录音」。

**追加块正文（**已定稿**，3 句）**

```
'卷盘的最后一句是问石头还在唱吗，然后说别停。'
'你没停。'
'他说他不要求你救谁——这句话今天仍然成立，你也不是来救谁的。'
```

**逐句职责**

| 句 | 职责 | 承接 |
|---|---|---|
| 1 | **引 L8 的原话**（引用，不改写） | L8 倒数三段：「石头还在唱吗？」「如果它在唱，别停。」 |
| 2 | **把陈述变成事实**——两字句，落在玩家身上 | 「你没停」= 你留下来了。**不解释、不评价** |
| 3 | **点主题**（Q2 的落点）：前任没替玩家做决定 | L8「我不要求你救谁」+ 叙事者自己的判断（不是前任的） |

**语气自查**

- 一本正经的描述 + 反转收尾：第 1 句是陈述（他在录音里问石头），第 3 句是反转（他说不要求你救谁——可你也不是来救谁的）；
- 冷幽默：有，但不抖机灵。不说教、不煽情、无 emoji、无网络流行语；
- 第 2 句只有 4 个字，与 `ENDING_LINES.stay` 第 2 句「前人把钥匙留给了这颗星球，你把它用上了」形成**同频**（都是短陈述 + 一句补充），不显得突兀；
- **不剧透**：追加块出现的唯一前提是玩家**已经获得过 L8 载体**（`readLogs` 含 L8）——此时 L8 的内容对该玩家已是可读的（`readableLogs` 会因 `alreadyRead` 直接放行），所以块内可以自由引用 L8 内容，不需要再藏。

**为什么不改 `ENDING_LINES.stay` 的第 2 句**：那 4 句是**基线**，任何玩家（获得不获得 L8 载体）都看同一份。基线里塞只有获得过 L8 载体才懂的话，是把「追加」偷偷做成了「替换」——反向成立就破了。

### 4.7 🟡 N-07 · `free` 结局的**计数式**追加块（**待定稿**，v3.2 讨论）

> **提出方式**：team-lead 提出——`free` 的语义是「没有目标了」，而 free 玩家大概率是「什么都经历了但什么都没留下」的人；是否值得给 free 一个**不带具体日志依赖**的通用追加块（例如按 `readLogs.length` 分档）。
> **与 §5 第 7 条的关系**：**不冲突**。§5 第 7 条禁的是**逐篇**联动（L1→free、L8→free……），禁不掉**计数式**联动。

#### 结论：**🟡 建议做，但必须满足四条约束；且门槛的措辞要改**

**做**的理由（三条）：

1. **free 的玩家画像与日志的题材高度重合**：free 玩家是「打通主流程但没选任何支线」的人——他们看过石头唱歌、看过前任留下的东西，只是没把它们变成任何成果。日志正是为这批人写的。**free 是唯一一条「日志的读者浓度天然最高」的结局**。
2. **它服务的是「反向成立」的另一面**：反向成立说的是「没获得载体时结局也完整」；计数式追加块说的是「获得得越多，free 的尾声越具体」——这是**在完整之上加厚**，不是**补缺**。两条不打架。
3. **它给了二周目一个具体的小钩子**：`readLogs` 跨周目保留，所以二周目选 free 时，计数块**必然出现**（只要一周目拿到过载体）。这是「你记得路」在 free 上的具体体现，而 free 恰恰是二周目里最容易被忽略的结局。

**四条约束**：

| # | 约束 | 理由 |
|---|---|---|
| **C-1** | **不出现具体篇目 id、不点名任何一篇** | 一旦点名（「你读过 L4 和 L8」），它就退化成逐篇联动，§5 第 7 条立刻被违反；也变成一份**成绩单** |
| **C-2** | **不出现「N 篇」这种数字** | free 的全部力量是「没有目标 / 没有数字」。一旦出现计数，free 就变成了「你的收集进度」——这是**把 free 变成任务清单**，与它的语义正面冲突 |
| **C-3** | **只分 1–2 档，且档位之间不构成优劣** | 分档的唯一目的是「让不同玩家看到不同的一句话」，不是为了给玩家评级。任何「读得越多、这句越华」的梯度都是评分 → 违反 §2.3 第 2 条 |
| **C-4** | **不改变 `ENDING_LINES.free` 基线一个字** | 与 N-01 / N-02 同一纪律 |

#### 判据（可判定）

```
条件 C_free_any := ngPlus.readLogs.length >= 1     // 获得过至少 1 篇载体
条件 C_free_all := ngPlus.readLogs.length >= 8     // 8 篇全获得
```

**建议只做 1 档**（`C_free_any`）。理由：两档需要一个「读得更多时换一句更有分量的话」的梯度，而那正是 C-3 禁止的评分感。**一档 = 所有人都看到同一句话**——它不是奖励，是**回声**。

> 若将来一定要做第二档，**建议改成「你手上有几样东西」而不是「你读了几篇」**（`readLogs.length` → 别的纯数量字段），并且第二档的句子必须**不显得更值钱**。但本轮**不建议做两档**。

#### 文案草案（🟡 待定稿，2 句 + 标题）

**标题候选**：`你也带了些东西`

**正文草案**：

```
'你把该捡的都捡了，该合的都合了，然后什么也没选。'
'东西还在背包里。没人规定它们要拿去干什么。'
```

**逐句职责**

| 句 | 职责 | 依据 |
|---|---|---|
| 1 | **把 free 的行为描述出来**，不评价 | `ENDING_LINES.free` 第 1 句「没有目标了」+ 第 3 句「剩下的时间都是你的」 |
| 2 | **反转**：东西都在，但**没人规定用途**——这是 free 的定义（东西在手、目标不在），也是它的自由 | 呼应 `DIALOGUE.ngplus` 的「别的都重新来」与 §7.1 G3 |

**语气自查**：一本正经（陈述你在做什么）+ 反转收尾（东西在，但没人规定）；不说教、不煽情、无 emoji、无网络流行语；**不出现数字、不点名**。

**为什么这个写法不会破坏 free 的「空」**：

- 它**没有增加任何新信息**——玩家知道自己的背包里有什么；
- 它**没有给出任何方向**——「没人规定它们要拿去干什么」是**取消规定**，不是给方向；
- 它**不区分玩家**——一档 = 所有人同一句；
- free 的基线那句「我建议什么都不做。难得。」**紧接着的上下文是「反正船也没了，信号器也修好了，剩下的时间都是你的」**——追加块放在这之后，恰好是同一口气的第三段：**东西在、时间在、没人规定**。

#### 待定稿的原因（诚实说明）

这一条我给的是**方向 + 判据 + 草案**，不是定稿，理由有二：

1. **它需要一次真正的文案校准**：free 是全游戏最短的结局（基线 3 句），加 2 句会**改变页面的呼吸感**。我没法在不看实际排版的情况下断言 3 句 + 2 句读起来是不是还是「空」。**建议 v3.2 落地时用真机看一眼**——如果读起来不空，就把追加块砍到 1 句（只留第 2 句「东西还在背包里。没人规定它们要拿去干什么。」）。
2. **它需要一个「与 N-01 / N-02 的一致性检查」**：N-01 / N-02 是**具体到某一篇**的联动（读 L8 → 出现关于 L8 的话），N-07 是**不指名任何一篇**的计数式联动。三者并置时，free 会不会显得像「泛泛版的 N-01」？这需要真机比对。**若发现 N-07 与 N-01 撞调，优先砍 N-07**（N-01 有 L8 原文支撑，N-07 没有）。

#### 工程量

比 N-01 / N-02 **略大**：判据是 `length` 而不是 `includes`，但**多出一个档位判断 + 一次措辞校对**。仍然是小。

这一节的价值在于**堵住后续反复讨论**。以下 8 条已逐条评估，并**逐条标明状态**：

- 🟥 **本批次已确认不联动（硬约束）** —— 后续批次不得推翻，除非有人能给出新的、文本上确实成立的钩子；
- 🟨 **待讨论** —— 允许在后续批次重新提起，但提起时须先过一遍本节的否决理由。

| # | 组合 | 状态 | 不联动的理由 |
|---|---|---|---|
| **1** | **任何日志 → stay 的**可见性 / 支线门禁 | 🟥 **硬约束** | 可见性由 `buildDone` 决定是**玩法门禁**；让叙事进度改玩法门禁会让「拿载体」变成任务清单 → 违反 §2.3 第 2 条 |
| **2** | **L8 → leave 的追加** | 🟥 **硬约束**（2026-10-21 team-lead 拍板否决） | 容易写成「你走对了」= **道德许可**；且会让没获得 L8 载体的 leave 显得次等 → 破坏反向成立（§3.1） |
| **3** | **L7 → stay** | 🟥 **硬约束** | L7 揭示「石头是公司要带回去的货物」。挂到 stay 会暗示**知道真相才有资格留下**，把获得记录变成资格线 → 违反 §2.3 第 2 条 |
| **4** | **L2 → leave** | 🟥 **硬约束** | L2「还剩不少燃料，够返程」很容易被读成「燃料够 → 你可以走」。挂上去等于给 leave 配一个**资源论证**，而 leave 的合法性不来自燃料 |
| **5** | **L1 → 任何结局** | 🟥 **硬约束** | L1 只交代「有过一个同伴、回声走了」。它不与任何**你的选择**构成因果；硬挂会让同伴线显得像某个结局的隐藏条件 |

| **7** | **任何日志 → free（逐篇）** | 🟥 **硬约束**（但**只限逐篇**） | free 是「没有目标了」——**空**是它的全部内容。加任何**具体到某一篇**的叙事块都会让 free 变成「有背景的空」；`ENDING_LINES.free` 现在那句「我建议什么都不做。难得。」的力量恰恰来自它前面没有铺垫。**注意**：本条**不禁**计数式联动 → 见 §4.7 N-07（🟡 待定稿） |
| **8** | **载体物品的 `desc` → 日志内容** | 🟥 **硬约束** | GDD §6.1 已定：内容只走日志面板，不进 `items.ts` 的 `desc`（≤40 字，只放钩子）。保持 |

**另外两条「留在待讨论区」的条目**（本轮未拍板，不属于上面 8 条）：

| 组合 | 状态 | 说明 |
|---|---|---|
| **L3 → birthday** | 🟨 待讨论 | §3 总表里标为 🟡 v3.2 候选。「每天记石头唱几遍」与 birthday 的仪式感同族，但 L8 已经提供了更直接的承接句（§4.2），**同一份呼应做两遍会稀释**。建议：L8 存在就不做 L3 版 |

### 6.3 建议的实现形状（仅示意，不落码）

```
// game-core/src/dialogue.ts（示意）
export const ENDING_EXTRAS = {
  stay: [
    {
      title: '前任的最后一页',
      lines: [
        '卷盘的最后一句是问石头还在唱吗，然后说别停。',
        '你没停。',
        '他说他不要求你救谁——这句话今天仍然成立，你也不是来救谁的。',
      ],
      requires: (readLogs: readonly string[]) => readLogs.includes('L8'),
    },
  ],
  birthday: [
    {
      title: '他每天早上跟它说话',
      lines: [
        '前任每天早上跟它说话，每天晚上把录音放给它听。',
        '生日是他没有办过的一个。你办了。',
      ],
      requires: (readLogs: readonly string[]) => readLogs.includes('L8'),
    },
  ],
} as const;
```

要点：

- `requires` 收 **`readLogs` 数组**而不是整个 `SaveState`——纯函数、易测、不碰存档结构；
- 追加块**与结局 id 一一对应**，不与日志 id 一一对应（一个结局可能有多条追加、来自不同日志）；
- `ENDING_EXTRAS` 与 `ENDING_LINES` **物理分离**，避免改基线时误伤追加块。

### 6.4 验收标准（可判定）

> **措辞前提（2026-10-21 修正）**：`readLogs` 的语义是「**合出过载体**」（§2.1），不是「打开面板读过全文」。下表统一按「**获得过 L8 载体**」写，测试前置也按此构造（合成出 `log_reel1` 即写入 `readLogs`）。

| # | 验收项 | 判定方式 |
|---|---|---|
| 1 | `readLogs` 含 L8 的存档进 `stay` 结局页 → 基线 4 句**原样** + 追加块出现 | 浏览器实测 / 单元测试 |
| 2 | **`readLogs` 不含 L8** 的存档进 `stay` 结局页 → 只有基线 4 句，**无追加块**，页面无空标题、无占位、无「？？？」 | 单测 + 实测 |
| 3 | 同上，`birthday` | 同上 |
| 4 | `leave` / `teashop` / `free` 结局页**在任何存档状态下都无追加块**（v3.1 范围内） | 单测（4 种结局 × {`readLogs` 含 L8, 不含 L8}） |
| 5 | `readLogs` 缺失 / 脏数据（老存档、手改存档）→ 追加块判定为 false，**不报错** | 归一化单测 |
| 6 | 二周目（`cycle=2`）里，一周目**获得过** L8 载体 → 追加块**仍然出现** | 单测 |
| 7 | `save.ngPlus.readLogs` 含 L8 但 `logsFound` 为空（二周目载体已清零）→ 追加块**仍然出现** | 单测（这条专门防「用错字段」） |
| 8 | 本批次**未新增任何存档字段**，`schemaVersion` 未 bump | `git diff` 人工核对 + 存档契约测试 |
| 9 | **载体被消耗的情形**：获得 L8 载体 → 把它喂给别的配方消耗掉 → `readLogs` 仍含 L8 → 追加块**仍然出现** | 单测（这条专测「合出即记、消耗不收回」语义，§0.2 第 3 条论证） |

第 7 条与第 9 条是本批次最容易踩的两个坑：

- **第 7 条**：判据若误用 `logsFound`（本周目载体记账），二周目里追加块会**整块消失**——而玩家一周目明明拿到过。**验收必须显式覆盖。**
- **第 9 条**：判据若写成「载体还在背包里」或「玩家打开过面板」，那条「合出后被消耗」的路径就会让追加块消失。**追加式的全部价值就在于它不受载体存亡影响**，这条测的是这个价值本身。

### 基线（**不变**，供对照）

`ENDINGS.stay`：title「留下来」/ subtitle「你没有走。石头多了一个会回来的邻居。」

```
没有起飞。你的行李里多了一个能住人的地方。
前人把钥匙留给了这颗星球，你把它用上了。这大概是这里最像遗产的东西。
石头今天唱得比平时多三遍。多出来的部分，我在你的日志里也记了。
我建议你把这地方记成坐标。以后有人路过，至少知道这儿可以停。
```

`ENDINGS.birthday`：title「给石头过生日」/ subtitle「它唱了一首没人听懂的歌。」

```
它唱了一首没人听懂的歌。你鼓掌了。
这就算过完了。仪式感这东西，本来就是给活着的人准备的。
它记得今天。这一点比蛋糕重要。
许愿的时候它很安静。愿望的内容未知，但一定跟明天有关。
```
